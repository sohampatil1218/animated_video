Error 1/6: database.py:42 • Critical SQLi

“The application directly inserts user-controlled input into an SQL query without parameterized binding. An attacker may manipulate this input to modify the query logic and access unauthorized database information.”

⚠️ Why is this dangerous?

Because input is concatenated directly, special characters like ' OR 1=1 -- rewrite the query logic, bypassing authentication checks.

💥 Potential Impact

Full database exfiltration (passwords, emails, transactions) or data destruction via injected DROP TABLE statements.

📍 Affected Code & Target Line

File: database.py • Line to Modify: Line 42
Inside getUserAccountData(): Direct concatenation must be replaced with parameterized placeholders.

🌐 Attack Context

Route is mounted on public endpoint GET /api/v1/user/account. No rate limiting or input filtering is active.

💡 Remediation Strategy

Execute query using parameterized tuples: cursor.execute("SELECT * FROM users WHERE user_id = %s", (user_id,))
